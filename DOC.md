# Documentation direction for setup and customization

## Dials and scope

FORMALITY: 4 | DENSITY: 5 | ORNAMENT: 1

Authoritative sources: README.md, Docs/SETUP.md, the backend reference and the Markdown tutorials. HTML companions are generated from the tutorials. The approved implementation and its evidence are tracked in IMPLEMENTATION.md; earlier implementation records remain historical.

## Structure

Lead with the action and its owning source. Setup follows offline checks, server preparation, Unity configuration and online verification. Tutorials explain code ownership, a concrete edit and its verification. Use navigation on longer pages.

## One signature element

Use a concrete edit destination for every proposed outcome: the reader can identify the file or Inspector asset to change, the expected effect and the check that proves it. Sustain this through the source map, slice locations and customization examples.

## Voice

Use direct paragraphs for reasoning, tables for file responsibilities and checklists for work. Keep observed facts separate from proposals and historical verification. Avoid decorative bold, generic introductions, repeated conclusions, emojis, vague claims and connector clichés.

## Typography and layout

Markdown inherits the reader's typography. Future HTML tutorials use the existing system sans serif body, Consolas/system monospace code, a 68–75ch reading measure and 1.5 leading. Use sentence case headings, generous section spacing and horizontal table rules. Do not impose document typography on Unity scenes.

## Figures and color

Use one small Mermaid editing map, grounded in existing paths. Its brief is in `diagram-design/customization-map/brief.md`. Preserve the menu's documented ink, teal, white and pale field colors; reserve gold for focus rather than body text. Figures must distinguish proposed workflow from implemented behavior. Record validation limits next to the figure.

## Avoid

No essay-shaped opening or summary conclusion, repeated heading subtitles, all-caps display labels, card grids, gratuitous gradients, boxed tables, fake metrics, invented architecture or unverified success claims. Keep generated exports subordinate to their source.
